# FORTREX — Canonical Glossary
> The dictionary. Any doc or code that uses these terms means exactly this. Adopted from
> the founder's framework, aligned to FORTREX reality. Last updated: Sep 26, 2026.

## Product

| Term | Meaning |
|------|---------|
| **FORTREX** | The platform and company product. One public name, everywhere. |
| **Arena** | The competitive environment (the product surface where competition happens). |
| **Genesis** | The founding-member program. 10,000 seats, hard cap, enforced in code. |
| **Genesis Seat** | One of the 10,000 founding positions. Permanent 1.25× REX multiplier. |
| **Tournament** | A bounded competitive event with frozen rules and defined results. |
| **Season** | A group of tournaments over a period. |
| **League** | Long-term competitive classification (post-launch concept). |
| **Ruleset** | Tournament rules frozen for that tournament. Never changed mid-event. |
| **Citadel** | The private community room (Discord/Telegram) opening Nov 7. |
| **Weight bracket** | Account-size bucket so a $500 account competes fairly with $50,000. |

## People

| Term | Meaning |
|------|---------|
| **Trader** | A user participating in trading activities/competition. |
| **Verified Trader** | A trader meeting FORTREX verification criteria (broker-verified data). |
| **Partner** | A third-party collaborator (educator, creator, sponsor). |
| **Creator** | An audience-owning marketing/community partner. |

## Data & verification

| Term | Meaning |
|------|---------|
| **Broker Connection** | An authorized read-only data connection to a broker. |
| **Trading Account** | The external broker account being verified. |
| **Trade** | A normalized trading event (normalized: timezone, decimals, symbol, currency). |
| **Verification** | Validation of external trading data, direct from the broker source. |
| **Data Freshness** | The age of verified broker data. |
| **Score** | The competition performance metric. Versioned (v1.0, v1.1…) and reproducible. |
| **Score Version** | An immutable version of the scoring methodology. |
| **Leaderboard** | Ranked competition output. Never manually altered without an audit event. |

## REX & money

| Term | Meaning |
|------|---------|
| **REX** | Internal reward/economic unit. **Current law: no cash value, no cash-out.** Final legal characterization unresolved (see `REX-ECONOMY.md`). |
| **REX Ledger** | Immutable, append-only reward transaction history. Balance is computed, never stored/mutated directly. |
| **Reward** | A benefit earned through FORTREX (from winning, not from redeeming points — current law). |
| **Redemption** | Conversion of eligible reward balance into a permitted reward. **Does not exist pre-counsel.** |
| **Payout** | External settlement of an approved reward. **Does not exist pre-counsel.** |

## Integrity & operations

| Term | Meaning |
|------|---------|
| **Fraud Case** | An investigation of suspicious activity. AI never publicly accuses; humans decide. |
| **Dispute** | A user challenge to a platform decision/result. Appeals exist; leaderboards never silently change. |
| **Audit Log** | Immutable administrative/system record (who, what, when, before, after, reason). |
| **Incident** | An operational or security event (SEV-0 to SEV-3 per `OPS-RUNBOOK.md`). |
| **Eligibility** | Whether a user can enter/redeem/participate. |
| **Activation** | The point where a user receives core value (precise definition: research/universe/08). |
| **Retention** | Continued meaningful use. |
